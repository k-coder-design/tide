# Tide — plan

A private iPhone app for tracking libido dynamics: partnered sex, other sexual activity (masturbation, sexual dreams, fantasies) and daily desire (1–5). For personal use only, data stays on the device.

| T17 | **Encrypted storage as built (phase 2)**: the database lives in memory; after every change its image is encrypted (AES-GCM, random 256-bit data key) and written to one of two files in the phone's private storage in turn. Each file carries a save number that is authenticated with the data, so a save cut off mid-write is detected and the previous file is used. If saved data cannot be decrypted (key missing or wrong), Tide stops with an error and never starts empty over it. Screens show only what works: the pill and bleeding blocks on Today, Insights, lock, backups and Health import arrive with their phases. | 17.11.2026 |
| T18 | **Bleeding starts a cycle, spotting does not.** Flow light, medium or heavy (and a Health flow record without a level) is bleeding: it forms episodes, and the first bleeding day of an episode starts a new cycle. Spotting is recorded and counted separately (spotting days per month, spotting days around an episode, spotting between episodes) and never starts an episode or a cycle; spotting before or after bleeding does not change an episode's start or length. The user tells them apart when choosing the flow; Tide does not guess. | 17.11.2026 |
| T19 | **Desire is rated 1–5, satisfaction stays 1–10.** A coarser daily scale is quicker to answer and steadier from day to day. Ratings already entered on the 1–10 scale were converted by schema migration 2: halved and rounded up (1–2 → 1, 3–4 → 2, 5–6 → 3, 7–8 → 4, 9–10 → 5). | 17.11.2026 |
| T20 | **Updates install by themselves.** Tide looks for a new version when it opens, each time it comes back to the screen and every 10 minutes in use. The new version downloads in the background and the app switches to it as soon as that is safe: at once when Tide is off screen, otherwise after a few seconds without touches, never while a form or sheet is open, a text field is in focus or a save is in progress. The open tab is kept and "Tide updated" shows for a moment. The check only fetches the app's own files, never journal data. | 17.11.2026 |
| T21 | **App lock as built (phase 3)** — Face ID part removed by T22. A 4-digit PIN on Tide's own keypad (as on the Lock mockup); turning the lock on asks for it twice and warns that a forgotten PIN cannot be reset. With the lock on, a new random data key replaces the browser-kept one and the saves are re-encrypted with it; the key is stored only wrapped — by the PIN (PBKDF2-SHA256, 600 000 iterations) and, if Face ID is on, also by the secret of a passkey read through the WebAuthn PRF extension after Face ID (iOS 18+; the passkey is kept by iCloud Keychain like any other and shows there under the site's name as "Tide"). Locking closes the in-memory database and clears the key: nothing of the journal stays in memory. Wrong PINs: four free tries, then waits of 30 s, 1 min, 5 min and 15 min, kept across restarts. Auto-lock after the chosen time in the background — immediately, 1 (default), 5 or 15 minutes; closing Tide always locks it; a lock button on Today. Turning the lock off asks for the PIN or Face ID and gives the same key back to the browser's keeping. While Tide is off screen a plain cover with the icon replaces the journal, for the app switcher snapshot. With the journal open behind the lock, updates (T20) wait until Tide leaves the screen, so a reload never locks it mid-use. The name "Tide" and the wave icon stay neutral. | 17.11.2026 |
| T22 | **No Face ID — the PIN only.** Face ID is removed from the lock screen, Settings and storage. A lock record saved by v0.3.0 loses its passkey-wrapped copy of the data key on the next start, so only the PIN opens the journal; a passkey created then stays in the Passwords app until the user deletes it there. | 18.11.2026 |
| T23 | **Logging past days.** Arrows by the date on Today step back day by day (never past today); desire and the four quick-log tiles then apply to the chosen day, its title reads Yesterday / the weekday / the date, and "Back to today" returns. A tap on a day in This week jumps to it. In the Journal calendar a day without desire shows "Desire — not rated", which opens the rating for that day. The entry form keeps its date field. | 18.11.2026 |
| T24 | **A missing journal is never replaced quietly.** After the first save, IndexedDB also keeps a note (`saved`) next to the key. If on start the key is there but both save files are missing or empty and the note says a journal was saved, Tide stops with "Your journal is missing" instead of opening an empty journal over it, before the PIN too. A key without the note (a first launch cut off before its first save) still opens a new journal; journals from older versions get the note on their next launch. "Start a new journal…" asks a second time, then forgets the old key and the PIN and opens an empty journal with the lock off; the core refuses it while any save is present, so it cannot erase a journal. Prompted by the save files vanishing three times in the desktop app's browser while IndexedDB stayed; quick reloads in that browser and in Chromium did not reproduce it, so the cause is not known. | 18.11.2026 |

## Web app limits on iPhone (affect phases 3 and 7)

- **Face ID**: no direct API; possible only through a passkey (WebAuthn PRF). Built in v0.3.0 and removed (T22): Tide uses the PIN only.
- **Reminders**: a web app cannot schedule a local notification; Web Push needs a server. Server-free option: an iOS Shortcuts personal automation that shows a neutral notification every evening and opens Tide.
- **Widget**: not possible for a web app. Option: a Shortcut on the Home Screen or Lock Screen that opens Tide straight on "quick add".
- **Removing the Home Screen icon deletes the data** — backups (phase 4) are essential.

0. **Setup** ✅ — Recallo studied, project created (builds, runs at iPhone size), data model approved ([docs/DATA_MODEL.md](docs/DATA_MODEL.md)).
1. **Design** ✅ — style A "Calm Water" (T10), design system (colors, type, components, light/dark), app icon C, and clickable mockups of all key screens at 428×926 (T16): Lock, Today, New entry, Journal (List / Calendar), Entry details, Insights (Libido / Cycle), Pill log, Settings. 2. **Core: the journal** ✅ (built 17.11.2026, v0.2.2) — encrypted local database (T17), quick logging from Today, daily desire with the week at a glance, the entry form and entry details (edit, delete), the journal as a list by day with filters and as a month calendar, desire and entries for past days from Today and the calendar (T23), partner labels (add, rename, archive), light / dark / system appearance, desire on a 1–5 scale (T19), offline mode (service worker) with automatic updates (T20), app icon C. Checked in a desktop browser at 428×926: entries survive a reload, storage holds only encrypted files; in Chromium a new build replaces the running one by itself, waiting while a form is open. Published 17.11.2026 at https://k-coder-design.github.io/tide/ (GitHub Pages, every push to `main`; install steps in README). Not checked yet: offline mode and the app on the iPhone itself.
3. **Privacy** ✅ (built 17.11.2026, v0.3.0; Face ID removed 18.11.2026, v0.3.1; missing-journal guard 18.11.2026, v0.3.2; softer light theme T25, v0.3.3) — optional app lock (T21, T22): 4-digit PIN, auto-lock, lock button on Today, change PIN, turning off with the PIN; the journal leaves memory when locked; a cover while Tide is off screen; neutral icon and name; Tide stops instead of starting empty when its saves disappear (T24). Checked in Chromium at 428×926: lock on and off with the journal intact, wrong-PIN waits survive a reload, auto-lock immediately and after a pause, the cover when off screen. Not checked yet on the iPhone: whether iOS takes the app switcher snapshot after the cover appears.
4. **Backups and moving** — encrypted backup file with a password, saved through the Share sheet (T14), restore (replace / merge), backup reminder, delete all data; one-time import of menstrual history from an Apple Health export (T12) — if it fails, the cycle section is removed (T11). ✅ when a backup from the old phone fully restores on a new one.
5. **Analytics** — frequency by week / month for both streams, desire with a moving average, heat-map calendar, period comparison.
6. **Medications and cycle** — medication courses, contraceptives shown on sex events automatically, courses overlaid on charts and simple findings (for example desire before and after a change of medication); the cycle section (T13): daily flow, pill log, symptoms, bleeding episodes and cycle analytics, a summary for a doctor.
7. **Habit** — reminders and a quick-add shortcut (see the limits above).

Phases 1–5 give the first useful version.
